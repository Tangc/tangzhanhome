# OpenClaw 对接飞书机器人额度告急？两招教你彻底解决！

> 唐斩的第 141 天第 162 篇分享。

所有正在使用 OpenClaw 对接飞书机器人的朋友（也就是咱们常说的“小龙虾”用户），**请立刻执行以下检查**！否则，你的免费机器人额度可能即将耗尽！

## 🚨 紧急检查：你的额度还安全吗？

1.  打开 [飞书开发者后台](https://open.feishu.cn/app)。
2.  选择你的机器人应用，在左侧菜单中找到 **“日志检索”**。
3.  在右侧的服务端日志中点击 **“查询”**。

**关键指标：**
如果在查询结果中，你看到每分钟都有一次 `/open-apis/bot/v3/info` 接口调用，那么恭喜你，**你中招了**。

这种情况持续下去，大约 7 天左右你就会收到飞书的额度预警，提示“企业免费额度已消耗 90%”。一旦耗尽，你的机器人将彻底停摆。

## 🔍 原因揭秘

不要慌，这不是安全漏洞，而是 OpenClaw 的**心跳检查机制**导致的。

为了确保所有 Channel（通道）稳定可用，OpenClaw 默认每 **60秒** 会探测一次通道的存活状态。不幸的是，飞书插件使用了 `/open-apis/bot/v3/info` 接口作为探测手段，而这个接口的调用是**计入免费额度**的！

每分钟一次，全天候不间断，额度自然跑得飞快。

## 🛠️ 彻底解决的两个方案

这里教大家两种彻底解决的办法，请根据你的实际情况选择。

### 方案一：针对 `m1heng` 版飞书插件用户

如果你使用的是 `m1heng` 开发的飞书插件（[GitHub 仓库](https://github.com/m1heng/clawdbot-feishu)）：

1.  **定位文件**：找到插件的探测文件，路径通常在：
    `~/.openclaw/extensions/feishu/src/probe.ts`
    *(注意：`.openclaw` 是隐藏目录)*

2.  **替换代码**：
    先备份该文件，然后将内容替换为**带缓存版本**。
    你可以直接复制这位博主提供的优化代码：[https://xx0a.com/blog/openclaw-feishu](https://xx0a.com/blog/openclaw-feishu)

3.  **重启服务**：
    修改完成后，执行以下命令重启网关：
    ```bash
    openclaw gateway restart
    ```

    *注：如果重启失败，请使用备份文件恢复。重启成功后，请再次观察机器人日志确认调用频率是否下降。*

### 方案二：修改 OpenClaw 核心配置（官方插件用户适用）

如果你使用的是官方插件，或者想从根源解决问题，可以调整 OpenClaw 的健康检查间隔。

1.  **定位核心文件**：
    找到 OpenClaw 安装目录下的 `server-constant.ts` 文件。
    以 macOS (Homebrew 安装) 为例，路径通常在：
    `/opt/homebrew/lib/node_modules/openclaw/dist/gateway/server-constant.ts`

2.  **修改检测间隔**：
    打开文件，找到第 32 行附近的变量 `HEALTH_REFRESH_INTERLVAL_MS`。
    默认值通常是 `60_000`（即 60 秒）。
    建议修改为 `86400_000`（即 24 小时检查一次）：
    ```typescript
    // 原代码
    // export const HEALTH_REFRESH_INTERLVAL_MS = 60_000;

    // 修改后（一天一次）
    export const HEALTH_REFRESH_INTERLVAL_MS = 86400_000;
    ```

3.  **重启服务**：
    执行命令重启网关：
    ```bash
    openclaw gateway restart
    ```
    重启后，同样需要观察日志确认是否生效。
